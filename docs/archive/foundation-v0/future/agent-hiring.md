# Future Concept — Agent Hiring

**Status:** Future Registry; not authorized for V1 implementation

## Purpose
Create new agent positions in response to approved real-world company requests.

## Underlying architectural insight
New agents should enter through governed requisition, qualification, onboarding, residence, and assignment.

## Potential inputs
Approved requisition, job specification, budget, Academy candidates or runtime templates.

## Potential outputs
Registered Agent, assigned home, permissions, probation plan, team placement.

## Dependencies
Company campuses, City Hall, Treasury, Academy, identity registry.

## Risks
Agent sprawl, duplicate capability, unmanaged cost, unclear accountability.

## Possible V1-compatible hooks
V1 should preserve stable IDs, event provenance, capability labels, and audit history so this concept can be added without rewriting the core domain. No dedicated UI, buildings, workflows, or runtime logic are authorized now.

## Explicitly not active
Claude Code must not implement this concept unless the Active Mission is formally amended.
