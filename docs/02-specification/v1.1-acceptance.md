# V1.1 Acceptance — Agent City

**Foundation:** 1.0
**Mission:** V1.1 — Operational Readiness and First Real Build
**Authority:** Mandatory acceptance criteria for the active mission
**Ratified:** 2026-08-03 at `AC-102`

---

## 0. Standing and relationship to V1 acceptance

This document **supersedes nothing** in `docs/02-specification/v1-acceptance.md`. V1's `F-01`–`F-12` and `V-01`–`V-08` remain the frozen V1 record and remain **mandatory** — see §2.

V1.1 requirements use a **disjoint namespace**: `F-101` onward and `V-101` onward. No V1 identifier is reused, renumbered, or re-graded.

A requirement here is satisfied only when it is **proven**, by a named automated test, a retained evidence artifact, or a recorded operator act. "Implemented" is not "accepted."

## 1. Test environment

Unchanged from V1: macOS primary; current Chrome and Safari; viewports **5120×1440** (primary), **3840×1080**, and **2560×1440**.

Added for V1.1:
- The **mock runtime remains the default** for every automated suite. Real-path coverage is a separate, explicitly-invoked suite.
- A **live two-process configuration** (frontend against a running `apps/api`) is required for the integration suite. `http://backend.test` — a hostname that never resolves — is not a live backend and does not satisfy any requirement here.
- The browser suite runs with `workers` **pinned in configuration**, not in prose.

## 2. V1 behaviours that must not regress

**Every V1 acceptance requirement continues to pass in mock mode throughout V1.1.** `F-01`–`F-12`, `V-01`–`V-08`, and the V1 ultrawide, persistence, failure/recovery, idempotency, accessibility, performance, and reduced-motion sections all remain mandatory.

A V1 regression is a **mission stop condition**, not a tradeoff.

`v1-canonical-run.json` must remain **byte-identical**. The mock runtime is the regression baseline and may not be modified.

## 3. Primary V1.1 operator journey

The mission outcome, performed by the operator personally, **unassisted, end to end, in one continuous session**, against the real backend, **with no seed script and no hand-submitted command**:

1. On a machine that has never run Foundry, run **one documented command**; reach a working Foundry.
2. Reach an approval-capable state **without reading a token out of a terminal**.
3. Submit **one bounded objective** as free text within the validated envelope.
4. Observe an out-of-template objective **rejected** with a structured, visible reason and zero mutation.
5. Read the **structured plan** the system produced — stages, requirements, acceptance criteria, workspace, risk class.
6. **Authorize execution** as an explicit act, having read exactly what will run.
7. Observe an unauthorized execution attempt **refused** with zero side effects.
8. Watch **real** Architect, Builder, and Inspector stages progress, every transition originating from backend authority.
9. Observe a Builder self-certification attempt **rejected**.
10. Observe **Inspector validation** of the real artifact.
11. Resolve **one real approval** — approving in one run, rejecting in another — and observe the difference in outcome.
12. Observe the **operator-approved** Warehouse upgrade.
13. Receive the artifact and review its evidence: logs, exit status, write-scope diff, independent test output.
14. **Restart both processes** and find the same truth.

## 6. Performance

Budgets carry forward from V1 unchanged: **45+ FPS target** in world mode, **30 FPS minimum** under full panels, at all three target viewports.

Added for V1.1:
- The **95th-percentile frame time is the gating number**, not the average. PV1-040 records the tail already implying ~36.9 FPS against the 45 FPS target.
- A fresh baseline is measured at `AC-117` **against a tree that includes commit `e5378aa`** (reconciliation N-04), before any `AC-118` work begins.
- `AC-118` re-measures before and after, and reports the tail.
- **Raising or removing a budget to make a measurement pass is prohibited.**

## 7. Definition of done

V1.1 is complete only when **all** of the following hold:

1. Every `F-101`–`F-134` and `V-101`–`V-106` requirement passes.
2. Every V1 acceptance requirement still passes in mock mode; `v1-canonical-run.json` is byte-identical.
3. Every V1 exclusion and every V1.1 exclusion remains unimplemented, verified against source.
4. Zero typecheck, lint, or build errors; the full unit/integration suite green; the real-path suite green; the cross-process integration suite green; accessibility, performance, and recovery suites green.
5. **Documentation matches implementation, including status metadata** — the clause V1 satisfied only narrowly.
6. **Finding 6 is closed with diagnosis, or explicitly re-carried with a diagnosis and retained reproduction evidence** (Decision 5). Closure by assertion is prohibited.
7. Decision **D-8** is resolved.
8. **The operator personally performs the §3 journey**, unassisted, end to end, in one session.

**Automated output alone cannot satisfy this gate.** No mandatory test may be waived, and no excluded feature may be substituted for a failing required one.

## 8. Explicit non-goals

Restated so the boundary is not inferred: V1.1 does not add world objects, districts, institutions, citizens, or interiors; does not build an authentication system; does not deploy, publish, or host anything; does not perform any external data collection, business discovery, website assessment, or outreach; does not spend money or contact any real party; does not promote anything from the Future Registry; and does not replace the mock runtime.
